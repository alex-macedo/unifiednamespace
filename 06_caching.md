## What is Caching?

Caching solves a common problem in distributed systems: **network latency** and **request overhead**. When multiple services are spread across different networks, it takes time for requests to travel between them. Caching stores frequently requested data or resources locally on each service, reducing the number of requests made to other services.

Let's illustrate this with an example:

Suppose we have two e-commerce services: `product-service` and `order-service`. Each service is hosted on different servers, which are geographically far apart. When a customer places an order on `product-service`, it needs to fetch the product details from `order-service`.

Without caching, each request would travel between these servers, resulting in significant latency and increased network overhead.

## Key Concepts

1. **Cache**: A store that temporarily holds frequently requested data or resources.
2. **Cache Hit**: When a request is served directly from the cache without needing to access the original source (e.g., database).
3. **Cache Miss**: When a request cannot be found in the cache, requiring access to the original source.

## Using Caching

Let's use caching as an abstraction to reduce network latency and improve performance.

### Example: Cache Configuration

Assume we want to configure caching for our `product-service`. We'll store frequently accessed product data in memory (RAM) instead of fetching it from the database every time.

```yml
# product-service configuration file
cache:
  type: 'in-memory'
  expiration: 10m // cache expires after 10 minutes
```

In this example, we're configuring caching to use an in-memory store with a 10-minute expiration policy. This means that cached data will be refreshed every 10 minutes.

### Explanation of Code Block

```yml
cache:
  type: 'in-memory'
  expiration: 10m // cache expires after 10 minutes
```

*   `type`: specifies the caching mechanism used (in-memory in this case).
*   `expiration`: sets the time period after which cached data will be refreshed.

### Explanation

When we start our application, it checks the cache for frequently requested product data. If the data is found in the cache, it serves it directly from memory without accessing the database. This reduces network latency and request overhead.

However, if the data is not found in the cache (a **cache miss**), it fetches the data from the original source (database) and stores it in the cache for future requests.
